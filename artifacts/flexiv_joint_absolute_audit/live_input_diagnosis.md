# 实际起始输入的动作预测核对

实际起始输入下，当前 connecter_1010 checkpoint 的无 RTC 预测缺少对应示范中的下降动作。该偏差在模型输出中已经存在；本次未修改真机控制参数，也未驱动机器人。

使用 session_1791641121079097907_1125482 的 tick 0 主相机、腕相机、state 和 prompt，加载配置中的 full_weights.pt 与 norm_stats，采用 10 步采样，关闭 RTC。比较第 19 行目标，即当前 20 帧启动执行段的最后一个目标。对应示范为配置所选首个 episode 的第 19 行 action。

| 目标来源 | X 位移 / mm | Y 位移 / mm | Z 位移 / mm |
| --- | ---: | ---: | ---: |
| 对应示范 action[19] | 6.686 | 1.231 | -6.695 |
| 实际输入预测，seed 0 | 5.520 | 1.152 | 0.416 |
| 实际输入预测，seed 1 | 6.549 | 1.179 | 0.048 |
| 实际输入预测，seed 2 | 4.089 | 2.067 | -0.436 |

位移由 Rizon4 URDF 的标称关节运动学估算，以本次实测 TCP 与关节状态恢复工具变换。数值描述预测目标，不能替代真机实测运动轨迹，也没有直接测量物体目标位置。比较以用户确认起始输入与训练数据一致为前提。

模型生成了部分向前动作，但三个 seed 的下降量均明显不足。初始 state 一致不能保证输出正确；采样结果本身也有差异。后续实际 tick 32 输入中，三个 seed 的第 19 行 J6 目标分别为 0.94068、0.94640、0.95594 rad，低于当时实测 0.96325 rad，说明进入偏离状态后仍有继续偏离的预测。单个关节的方向本身不能代表任务成功与否，应结合完整 TCP 轨迹判断。

另以 tick 0 和 seed 0 比较完整 prefix + suffix 前向及缓存 prefix、重复 suffix 的推理路径，均运行完整 10 步 Euler 积分：所有 32 行中的最大关节差异为 0.03798°，平均差异为 0.00726°。完整前向的第 19 行 TCP 位移为 [5.444, 1.144, 0.442] mm，缓存前向为 [5.520, 1.152, 0.416] mm；两者同样缺少下降。将预处理观察转换为 embed dtype 后，此样本结果未变。此核对排除了该样本上缓存计算差异是主要原因，不能覆盖所有输入。

结果支持将下一步诊断放到 checkpoint 的动作预测及闭环恢复能力，而非继续调整运动上限。RTC 和插值影响轨迹衔接，不会自动生成缺失的任务动作。尚不能仅凭这些结果确定是训练收敛、数据分布还是权重选择导致，需在训练机对同一个 checkpoint、同一观察进行动作推理比较，并比较不同训练步数 checkpoint 的物理动作与 TCP 轨迹误差。

原始结果：live_capture_predictions.json、live_forward_parity.json。完整前向核对脚本：live_forward_parity.py。
