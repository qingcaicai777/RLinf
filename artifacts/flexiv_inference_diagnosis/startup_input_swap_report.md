# 首段动作预测与输入替换排查

本次检查解释整条 episode 的绝对关节角曲线接近、启动动作却偏离的现象。使用当前 connecter_1010 checkpoint、当前归一化统计及 10 步采样，分别运行 5 个固定 seed；每个 seed 对六组输入使用完全相同的初始噪声。全部离线运行，没有驱动机器人。

实机输入来自 `session_1791641121079097907_1125482/tick_000000_*`，示范参考为 episode 0。实机与示范初始关节状态最大差异约 0.00285°，夹爪差异 0.03 mm。只替换 state 时，完整模型输出与示范输入完全相同。因此，此捕获样本不能再归因于初始关节位置不一致。

## 为什么之前曲线容易误导

之前每帧都重新输入真实示范观察，且只保留预测 chunk 的第 0 个 action。它不检验启动时连续执行的 action[0:20]，也没有让前一步的错误改变后续输入。整条 episode 的第一步关节 MAE 为 0.180°，直接保持当前 measured state 的基线也只有 0.242°。前 20 帧的第一步预测 MAE 为 0.264°，保持当前状态的基线为 0.169°。这里比较的是对示范 command 的误差，不能据此说保持不动可以完成任务。

下表为 action[19] 相对输入关节状态的变化，模型值取五个 seed 平均：

| 来源 | J2 / ° | J6 / ° |
| --- | ---: | ---: |

即使用原始训练观察，首段动作幅度已经明显小于这条示范。替换实机图像进一步改变输出，此处腕相机对 J6 的影响较主相机大；这不能证明相机损坏、配置错误或图像不可用。

用 Rizon4 标称 URDF 和示范首帧恢复的工具变换估算，示范 action[19] 的 TCP Z 位移为 -6.69 mm；示范输入预测平均为 +0.30 mm，实机输入预测平均为 +1.22 mm。示范输入五个 seed 的 Z 范围为 [-1.52, +3.78] mm，实机输入为 [-0.44, +4.29] mm。这里只描述标称运动学下的预测目标，不能代替实测 TCP 轨迹，也未测量实机目标物体位置。

## 结论与下一步

代码路径中首个 bootstrap chunk 从第 0 个 action 开始，首次推理没有历史 committed actions，因此无需 Jacobian RTC 就能复现首段预测与示范的偏差。此实验没有发现关节顺序、弧度单位或初始 state 是该样本的原因。

现有证据把问题定位到当前 checkpoint 的首段动作预测和实机图像下的变化，而非单纯通信延迟。它尚不能区分训练不充分、多条示范的起步时序差异、视觉泛化或原始训练推理实现的差别；不能据此直接判定采集脚本有错误。

下一步应在训练侧用同一 checkpoint、episode 0 首帧和固定噪声核对完整 32 步预测，并比较多个 checkpoint 的 action-state 增量、首段 TCP 位移和完整 chunk 误差。若训练侧相同，应检查示范起步时序和训练收敛；若不同，应定位训练侧和部署侧的计算差异。已有本地完整前向与缓存前向核对也都缺少下降，不能指望仅关闭缓存解决。
