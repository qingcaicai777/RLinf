# 无滤波的交接延时与目标连续性优化

本次验证比较 CUDA graph 对延时和原始动作的影响，并检查缩短执行窗口是否减少新旧预测的不一致。没有加入滤波、插值或限幅，也没有启动真机。

## 普通采样与 RTC 采样

使用 joint_abs_1007、固定的合成图像和关节状态、10 步采样，分别预热后测量五个随机种子。每组开启 graph 后与关闭 graph 的物理动作和 raw 模型动作逐元素比较，最大误差均为 0。

| CUDA graph | RTC 上下文 | 模型调用中位数（ms） |
|---|---|---:|
| False | False | 221.67 |
| False | True | 104.83 |
| True | False | 91.49 |
| True | True | 103.36 |

Jacobian 模式的普通采样现在使用 CUDA graph，guided 采样仍使用独立的编译 autograd 路径。该修改保持动作数值一致，缩短的是模型调用时间。计划交接时刻保持不变。

## 缩短执行窗口

使用 peg_insertion_ok 第一条演示的真实图像和状态，在 frame 100、300、450 上分别使用三个相同随机种子。每个调度的旧预测和新预测都使用 10 步。模型在旧观测上生成旧块，在同一个当前观测上生成新块；RTC 上下文按对应调度截取。delay_steps 固定为 K−R=4。

| K/R | 同一交接帧的新旧预测最大差值（度） | 交接目标步长（度） | 对实测未来 q 的 MAE（度） |
|---|---:|---:|---:|
| 22/18 | 1.2771 | 1.3797 | 0.2418 |
| 20/16 | 0.9999 | 1.0350 | 0.2296 |
| 16/12 | 0.7344 | 0.7744 | 0.2230 |

数值为九组样本的中位数。16/12 缩短旧预测的执行窗口，同时保持约 133 ms 的推理预算。它在这些样本中减小了预测衔接变化，但没有消除跳变。输入来自训练演示，观测使用记录的真实轨迹，结果不代表闭环真机成功率。

服务器日志 max_same_time_change_deg 比较同一个计划交接帧的新旧预测，可用于区分正常运动与预测变化。机器人日志 late_ticks 用于判断实际交接是否迟到。
